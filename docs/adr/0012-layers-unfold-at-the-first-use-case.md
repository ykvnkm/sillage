# ADR-0012. Слои разворачиваются на первом сценарии, а не на первом API

- **Дата:** 2026-10-11
- **Статус:** принято
- **Фаза:** 2, шаг 2.3
- **Уточняет:** [ADR-0001](0001-clean-architecture-boundary.md)

## Контекст

ADR-0001 откладывал расслоение до Фазы 3, «первого публичного API». Пересмотр
дорожной карты ([roadmap-product.md](../roadmap-product.md)) перенёс API на шаг 2.4.
Шаг 2.3 — первый код, который вызывается не из исследования, а будет вызываться
пользователем: сценарий «SMILES → профиль + уверенность + соседи».

Условие ADR-0001 для расслоения — «контракты, написанные до появления двух реальных
реализаций, почти всегда неверны». Реализация пока одна: логрег на фингерпринтах.
Но порт `OdorPredictor` уже нужен по другой причине: правила продукта (что
отклоняется, в каком порядке, какое число показывается и какое нет) должны
проверяться без модели, иначе каждый тест правила — это тест логрега.

## Решение

Разворачиваем `domain/`, `application/`, `adapters/`, `interfaces/` сейчас, на
сценарии, а не ждём HTTP.

```
domain/         Molecule, OdorProfile, Confidence, Refusal, OdorReport, ports.py
application/    PredictOdor
adapters/chem/  RdkitMoleculeReader, FingerprintReferenceLibrary
adapters/models ArtifactOdorPredictor, ArtifactScopePolicy
interfaces/     composition.py (единственная точка сборки), cli.py
```

Порты: `MoleculeReader`, `ScopePolicy`, `OdorPredictor`, `ReferenceLibrary`.
Контракт `OdorPredictor` сформулирован на уровне **молекулы**, а не матрицы
признаков: `predict(Molecule) -> OdorProfile`. Это делает его пригодным для GNN,
которой нужен граф, а не вектор.

Существующий `sillage.models` не переносится в `adapters/`: он общий для
исследования и продукта (обучение строит `OdorModel`, сервис его загружает).
Адаптеры оборачивают его. Наборы признаков переехали из `research/` в
`features/sets.py`: сервис обязан строить ровно те признаки, на которых обучалась
модель, и не может ради этого импортировать исследовательский код.

Шкала уверенности (`Confidence`, `BANDS`) переехала в `domain`: это обещание
продукта «likely значит ≈ 0.89», и GNN будет обязана его держать так же.

Правило зависимостей проверяется тестом `tests/test_layers.py`: `domain` и
`application` импортируются в чистом интерпретаторе, и тест падает, если при этом
загрузился RDKit, NumPy, sklearn, pandas, joblib, scipy или torch. Тест проверен на
намеренно внесённом `import numpy`.

## Сопутствующие решения

1. **Артефакт, версия 3.** `reference.json` хранит все 4777 молекул области
   определения с метками экспертов и частью сплита, а не только SMILES 3824
   обучающих. Сосед без меток ничего не говорит о запахе; часть сплита нужна, чтобы
   говорить пользователю, видела ли модель именно эту молекулу. Веса и метрики не
   изменились (macro AP 0.3546 до и после).
2. **Стереохимия отбрасывается явно.** Вход приводится к SMILES без стерео — ту же
   форму имеют обучающие данные — и ответ несёт оговорку `stereo_discarded`.
3. **scikit-learn, numpy, joblib — рабочие зависимости**, а не dev. Раньше
   сохранённая модель не загрузилась бы в окружении без dev-группы, то есть в
   будущем Docker-образе.

## Последствия

**Положительные.** Правила продукта тестируются на заглушках за миллисекунды. Смена
модели — правка одного файла `interfaces/composition.py`. API шага 2.4 получает
готовый сценарий и только сериализует его ответ.

**Отрицательные.** Контракт `OdorPredictor` пока выведен из одной реализации и
может потребовать правки, когда появится GNN. Это осознанная цена: правка
протокола из одного метода дешевле, чем тесты правил, привязанные к логрегу.
