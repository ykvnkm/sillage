# ADR-0014. Веса живут на HF Hub, деплой берёт их по ревизии и контрольной сумме

- **Дата:** 2026-10-11
- **Статус:** принято; пункт 6 (деплой на HF Spaces) отменён [ADR-0015](0015-public-deployment-is-deferred.md)
- **Фаза:** 2, шаг 2.6

## Контекст

До шага 2.6 веса существовали только в `models/` на машине разработчика: в git их
нет (`/models/` в `.gitignore`), и Docker-образ копировал локальную папку. Отсюда две
проблемы. CI не мог собрать образ, поэтому ошибку с системными библиотеками RDKit
(E-014) поймала ручная сборка, а не автоматика. И публичный сервис нельзя
развернуть из репозитория: ему неоткуда взять модель.

## Решение

1. **Реестр моделей — HF Hub.** `scripts/publish_model.py` загружает артефакт и
   model card в `<аккаунт>/sillage-<имя>`. Имя аккаунта берётся из токена.
2. **Закрепление — манифест в git.** Публикация пишет `deploy/hub.json`: репозиторий,
   **commit-хеш** загрузки (не имя ветки) и sha256 каждого файла. Смена модели в
   продакшене — это видимый diff этого файла в PR.
3. **Проверка сумм обязательна.** Файлы модели — pickle, а распаковка pickle исполняет
   код. `scripts/fetch_model.py` скачивает по закреплённой ревизии и удаляет любой
   файл, чья сумма не совпала с манифестом; сборка образа падает. Подменённый на Hub
   файл не попадёт в сервис, даже если кто-то перепишет ревизию.
4. **Один Dockerfile везде.** Локально, в CI и на Space образ собирается одинаково и
   скачивает модель сам; локальная `models/` в сборку не попадает.
5. **CI проверяет образ, а не только код.** Отдельная задача `image` собирает образ и
   прогоняет `scripts/smoke_test.py` против запущенного контейнера: страница, рисунок,
   «ванилин → ваниль», отказ для брома.
6. **Деплой — только после влития в `main`** и только если прошли и `checks`, и
   `image`. `scripts/deploy_space.py` загружает в Space ровно то, что разрешает
   `.dockerignore` (тест следит за совпадением списков), Space собирает тот же
   Dockerfile. Деплой считается законченным, когда публичная ссылка проходит тот же
   smoke-тест, а не когда закончилась загрузка.

## Почему HF Hub, а не GitHub Releases или DVC

- **GitHub Releases** хранят файлы, но не дают model card, метаданных и того места,
  где ML-модели ищут. Для портфолио модель на Hub видна как модель.
- **DVC** решает версионирование данных и экспериментов, а здесь одна модель и один
  потребитель. Отдельный инструмент с удалённым хранилищем ради четырёх файлов —
  инфраструктура ради инфраструктуры. Пересмотреть, когда моделей станет несколько
  (GNN, Фаза 2) или появятся версии данных.

## Последствия

**Положительные.** Образ собирается из чистого клона. Каждое изменение проверяется на
реальном контейнере. Какая модель работает в продакшене, видно из git.

**Отрицательные.** Публикация новой модели — ручной шаг разработчика с токеном на
запись (`publish_model.py`), за которым следует PR с новым `deploy/hub.json`. Это
сознательно: смена модели в продакшене должна проходить через ревью, а не случаться
от переобучения.

Бесплатный Space засыпает без трафика; первый запрос после паузы ждёт сборку и
загрузку около минуты.
