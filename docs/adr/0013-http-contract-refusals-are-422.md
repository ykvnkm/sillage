# ADR-0013. HTTP-контракт: отказ — это 422 с кодом причины, одна форма для всех отказов

- **Дата:** 2026-10-11
- **Статус:** принято
- **Фаза:** 2, шаг 2.4

## Контекст

Сценарий `PredictOdor` (шаг 2.3) возвращает либо отчёт, либо `Refusal` с кодом
причины. Отказ — запланированный ответ, а не ошибка: вне области определения модель
в шесть раз чаще ошибается катастрофически (E-008). HTTP нужно решить, каким
статусом и в какой форме это отдавать.

У FastAPI своё мнение об ошибках: невалидное тело запроса (пустая строка, лишние
символы, `neighbours: 1000`) возвращается как 422 со списком ошибок pydantic в
другом формате. Если оставить как есть, клиент получит два разных 422 с разными
телами в зависимости от того, *где* отказано — на схеме или в домене.

## Решение

1. **`POST /predict`: 200 — ответ, 422 — отказ.** Тело отказа одно:
   `{"refused": true, "reason": "<код>", "detail": "<текст>", "molecule": …}`.
   Ошибки валидации схемы перехватываются и отдаются в той же форме с кодом
   `invalid_input`. Клиент обрабатывает один формат.
2. **Коды стабильны:** `invalid_input`, `multiple_components`, `inorganic`,
   `charged`, `unseen_element`, `weight_out_of_range`. На них же построены метрики.
3. **Схемы ответа отделены от доменных типов** (`interfaces/api/schemas.py`). В
   ответе нет поля `score`: у неоткалиброванной метки единственное число,
   доступное клиенту, — `probability: null`. Добавить поле в доменный dataclass и
   случайно отдать его наружу невозможно.
4. **`sillage-predict --json` отдаёт ту же схему,** что и API. Один контракт, две
   точки входа.
5. **`/metrics` — сразу**, а не на шаге 2.9: двадцать строк `prometheus-client`.
   Кроме HTTP-метрик — отказы по причинам, сходство входа с ближайшей известной
   молекулой (дрейф входов), верхняя вероятность по полосам уверенности. Метки
   маршрутов — шаблоны, а не сырые пути: иначе сканер, перебирающий случайные URL,
   создаёт неограниченное число временных рядов.
6. **Модель загружается один раз при старте.** Нет артефакта — сервис не
   стартует, вместо того чтобы отдавать 500 на каждый запрос.

## Почему 422, а не 200 с флагом

200 с `{"refused": true}` честен по смыслу («запрос обработан, ответ — отказ»), но
ломает всё, что смотрит только на статус: балансировщики, дашборды доли ошибок,
`curl --fail`. 422 Unprocessable Content по определению значит «запрос понят,
синтаксически корректен, но обработать его нельзя» — ровно наш случай. 400 не
подходит: синтаксически запрос правильный.

## Образ

`Dockerfile` двухстадийный: uv ставит зависимости строго по `uv.lock` без dev-группы,
финальный образ получает только готовое окружение и модель, работает не от root,
порт берёт из `$PORT` (HF Spaces на шаге 2.6 ожидает 7860).

Веса не лежат в git, поэтому образ собирается из локального `models/` после
обучения, и CI образ пока не собирает. Это закрывается на шаге 2.6, когда веса
поедут на HF Hub и сборка сможет их скачать.

Известное ограничение: образ весит 1.02 ГБ, основное — RDKit, scipy, scikit-learn.
pandas и pandera нужны только модулю загрузки данных, но сейчас стоят в рабочих
зависимостях целиком. Разделение на extras — когда размер станет проблемой при
деплое, не раньше.
