# ADR-0017. Графовые сети обучаются в torch, а работают в сервисе на NumPy

- **Дата:** 2026-10-17
- **Статус:** принято
- **Фаза:** 2, исследования (журнал E-020)

## Контекст

Модель `odor-ensemble-v3` — среднее трёх компонентов: логистической регрессии,
бустинга на дескрипторах и пяти графовых сетей D-MPNN. Сети обучаются в PyTorch.
Сервис до сих пор обходился без torch: образ весит 274 МБ, ответ занимает ~10 мс на
одном потоке CPU ([ADR-0014](0014-model-weights-live-on-the-hub-pinned-by-checksum.md)).
CPU-сборка torch добавила бы образу несколько сотен мегабайт и одну тяжёлую
зависимость, хотя ради ответа на один запрос ему нужно совсем немного.

Прямой проход D-MPNN по одной молекуле — это несколько матричных умножений и сумм
по связям, на графе из 10–30 атомов.

## Решение

1. **torch — только для обучения.** Он лежит в отдельной группе зависимостей `gnn`,
   а не в `dev` и не в основных зависимостях. CI ставит его ради тестов сети, на
   Linux — CPU-сборку из индекса PyTorch, без CUDA. Тест `test_layers` проверяет,
   что ни API, ни CLI, ни построение графа не импортируют torch.
2. **Сервис считает сети на NumPy** (`models/graph_network.py`). Тест сверяет его
   выход с torch с точностью до 1e-5, в том числе после сохранения и загрузки и на
   молекуле без связей.
3. **Веса сетей хранятся в `graph.npz`** — это обычные массивы, которые читаются
   с `allow_pickle=False`. В отличие от `.joblib`, такой файл при открытии не может
   выполнить код.
4. **Бустинг компилируется так же, как раньше логрег**
   ([E-013](../journal/experiments.md)): все ~20 000 деревьев складываются в общие
   массивы, и спуск по ним идёт одновременно (`BoostedMultilabel`). Выход совпадает
   со sklearn до 1e-12, время на молекулу падает с 60 до ~8 мс.
5. **Формат артефакта — версия 4**: в карточке модели перечислены её компоненты.
   Версию 3 новый код читает как модель из одного линейного компонента. Обратного
   пути нет: старый код, открыв ансамбль, молча отдавал бы только его линейную часть.

## Последствия

- Ответ сервиса стал ~40 мс вместо ~10. Время уходит на признаки (~3 мс),
  бустинг (~8 мс), сети (~3 мс) и на то, что ансамбль считается дважды: для
  профиля запаха и для точки на карте.
- Любое изменение архитектуры сети придётся вносить в двух местах. Тест на
  совпадение не даст им разойтись незаметно.
- Модель со стереохимией получает молекулу в изомерной форме. Плоский SMILES
  остаётся ключом для справочника, названий и карты.
