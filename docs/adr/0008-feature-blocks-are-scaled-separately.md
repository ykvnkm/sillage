# ADR-0008. Блоки признаков масштабируются раздельно

- **Дата:** 2026-08-20
- **Статус:** принято
- **Фаза:** 1, шаг 1.5

## Контекст

Матрица признаков состоит из двух блоков принципиально разной природы:

- **фингерпринты Моргана** — 2048 разреженных столбцов, значения 0/1 (или малые
  целые для счётного варианта), уже находящиеся на общей шкале;
- **дескрипторы RDKit** — 216 плотных столбцов в несопоставимых единицах:
  молекулярная масса до 1347 рядом с числом колец в единицах.

Первая версия пайплайна применяла `StandardScaler` ко всей матрице. Результат
абляции выглядел содержательным: дескрипторы (216 признаков) обыгрывали
фингерпринты (2048), а добавление фингерпринтов к дескрипторам **ухудшало**
качество. Вывод был бы записан как свойство признаков.

Проверка заменой скейлера показала, что это артефакт обработки (журнал E-005).

## Механизм

`StandardScaler` делит каждый столбец на его стандартное отклонение. Для
морган-бита, загорающегося у 5 молекул из 3967, σ ≈ 0.035. После деления эти пять
строк получают значение около 28, тогда как нормально отмасштабированный признак
лежит в пределах ±3.

Последствия двойные. L2-регуляризация вынуждена давить коэффициенты при таких
столбцах, то есть информация из редких фрагментов теряется. И две тысячи
раздутых столбцов размывают бюджет регуляризации, отведённый на 216 информативных
дескрипторов.

`MaxAbsScaler` делит на максимум модуля: бинарные биты остаются 0/1, разреженность
сохраняется, раздувания не происходит. Но для дескрипторов он хуже
`StandardScaler`, потому что не центрирует и оставляет несопоставимые дисперсии.

## Решение

`logistic_regression` строит `ColumnTransformer` с двумя блоками:

| Блок | Скейлер | Почему |
| --- | --- | --- |
| столбцы с префиксом `morgan_` | `MaxAbsScaler` | уже на общей шкале, деление на σ раздувает редкие биты |
| остальные | `StandardScaler` | несопоставимые единицы; без центрирования lbfgs не сходится |

Принадлежность к блоку определяется **по именам столбцов**. Это стало возможно
благодаря решению из шага 1.2: `FeatureMatrix` носит имена вместе со значениями
(ADR-0006). Обоснованием там была будущая интерпретируемость; пригодилось раньше
и для другого.

Варианты с одним скейлером сохранены как модели `logreg-std` и `logreg-maxabs`,
чтобы находка воспроизводилась, а не осталась утверждением в тексте.

## Последствия

Измерено на стратифицированном сплите, набор `morgan-bin-r3+desc`, 3 сида:

| Масштабирование | macro AP |
| --- | --- |
| поблочное | **0.3420 ± 0.0126** |
| только MaxAbs | 0.3237 ± 0.0098 |
| только Standard | 0.2615 ± 0.0104 |

Разрыв 0.08 macro AP при неизменных модели, признаках и сплите — того же порядка,
что и весь разброс между наборами признаков внутри правильного пайплайна.

**Положительные.** Абляция снова измеряет признаки, а не обработку. Порядок
выводов на скаффолд-сплите тот же, то есть эффект не привязан к разбиению.

**Отрицательные.** Пайплайн усложнился, и его поведение зависит от соглашения об
именовании столбцов. Признак с префиксом `morgan_`, не являющийся фингерпринтом,
попадёт не в тот блок молча.

**Общий вывод, вынесенный в правила проекта.** Абляция сравнивает **пайплайны**,
а не признаки. Если обработка подходит одному варианту лучше, чем другому,
измеряется обработка. Любое сравнение наборов признаков обязано либо использовать
обработку, корректную для каждого, либо явно оговаривать это ограничение.

## Альтернативы

- **Один `StandardScaler` на всё.** Отклонено: занижает фингерпринты на 0.08 macro AP.
- **Один `MaxAbsScaler` на всё.** Отклонено: занижает дескрипторы (0.2181 против
  0.3055 на наборе `descriptors`).
- **Не масштабировать вовсе.** Отклонено: без масштабирования lbfgs не сходится за
  1000 итераций, а время обучения растёт с 0.11 с до 2.8 с на метку.
- **Отбирать признаки вместо масштабирования.** Отложено: отбор зависит от данных
  и обязан фититься на обучающей части; кандидат в Фазу 2.
